## ⚠ `worker/index.js` intentionally differs from `CHECKSUMS.sha256`

Every other file delivered in the vendor package still verifies byte-for-byte against the shipped
`CHECKSUMS.sha256`. **`worker/index.js` does not, and that is deliberate** — it carries one
Cloudflare D1 compatibility fix. This is recorded here so the mismatch is never mistaken for
tampering or an accidental edit.

**What was wrong.** `fieldAuditStatement()` built the descriptive-audit query by emitting one
`SELECT` per edited field joined with `UNION ALL`. Cloudflare D1 rejects compound `SELECT`
statements above **5 terms** (`too many terms in compound SELECT`, `SQLITE_ERROR 7500`). The edit
form submits every field at once, so any save touching 6 or more fields produced invalid SQL, threw,
and returned HTTP 500 / Cloudflare Error 1101. Project editing was effectively broken in production.

The defect was not visible before deployment because the package was validated only against local
SQLite (`node:sqlite`), whose compound-`SELECT` limit is 500. `AUDIT_CHANGE_HANDOFF.md` and
`VALIDATION_REPORT.md` both state that testing in a live Cloudflare account was never performed.

**What changed.** The field/value pairs now travel as a single bound JSON parameter and are expanded
into rows by `json_each()`, with before-values read from a `json_object()` snapshot of the same row.
`json_each()` has no term limit, so the query scales to any field count. Scope of the change:

- One function body in `worker/index.js` (~15 lines). No other code touched.
- **No database schema change.** No migration required.
- No change to the function signature, so both call sites (`/api/projects/:id/fields` and
  `/api/projects/:id/development`) are unmodified.
- No change to permissions, business-unit behaviour, or `ALLOW_PLATFORM_AUTH`.

**Audit behaviour is preserved exactly**: before/after values, actor identity, project name,
timestamps, one audit row per save, and no entry when nothing actually changed. Before-values are
still read inside the same statement, which stays in the same `batch()` as the `UPDATE`, so
concurrency accuracy and atomicity are unchanged.

**Verified against real Cloudflare D1** on 2026-09-09 using a temporary database restored from the
production backup — 1 field, 6 fields and all 19 editable fields, plus unchanged-field exclusion and
a forced-failure rollback. Details in the commit and in `BACKUP_AND_RESTORE.md`'s sibling notes.

If the vendor issues a corrected package, re-apply this fix or confirm their version resolves the
same D1 limit before overwriting the file.

## Deploy

Steps 1–2 are interactive and must be run by the operator.

```sh
# 1. Authenticate (opens a browser)
npx wrangler login

# 2. CONFIRM THE ACCOUNT before anything writes to it.
#    This must show the CLIENT's account, not a personal one.
npx wrangler whoami

# 3. Apply the six migrations — EXACTLY ONCE.
#    0001/0003/0004/0005 use ALTER TABLE ... ADD COLUMN and are NOT idempotent;
#    a second run fails with "duplicate column name". Note --remote: --local and
#    --remote are one word apart and hit completely different databases.
for f in drizzle/*.sql; do
  npx wrangler d1 execute DB --remote --yes --file="$f"
done

# 4. Verify the schema landed (expect 10 tables)
npx wrangler d1 execute DB --remote --yes \
  --command "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"

# 5. Build and deploy
npm run deploy       # = npm run build:pages && wrangler pages deploy
```

On first deploy wrangler will prompt to create the Pages project. Accept the name
`dnc-tracker-pilot` so it matches `wrangler.toml`.

### After the first deploy

```sh
# 6. Seeding runs on the first API request. Load the site once, then verify:
npx wrangler d1 execute DB --remote --yes \
  --command "SELECT COUNT(*) AS projects FROM projects"          # expect 74
npx wrangler d1 execute DB --remote --yes \
  --command "SELECT COUNT(*) AS users FROM user_directory"       # expect 73

# 7. Provision the first administrator. NOTHING can sign in before this:
#    PILOT_CREDENTIALS is empty by design and all 73 seeded directory entries
#    are 'pending' with no password hash.
node pages-test/make-login.mjs 'first.admin@example.com' 'a-strong-password'
#    ^ prints an UPDATE statement; pass it to:
npx wrangler d1 execute DB --remote --yes --command "<paste the UPDATE>"
```

The password must satisfy `validatePassword()` if it is ever changed through the UI:
**10+ characters, with upper, lower, digit and a special character.**

## R2 — profile photograph storage

Bucket `dnc-tracker-assets` exists in the client account (created 2026-09-09) and is bound in
`wrangler.toml` as `BUCKET`. **The binding is not live until the next deploy.**

`env.BUCKET` is guarded at every use site, so the application ran correctly without it — verified
against the deployed build before the bucket existed:

| Endpoint | Without R2 (previous state) |
|---|---|
| `GET`/`PUT` `/api/users/:id/avatar` | `503 "Photo storage is temporarily unavailable."` |
| `importRequestedProfilePhotos()` | Returns early, retries on the next admin visit |
| Everything else — projects, exports, Help PDF, roles, admin, audit | **Unaffected** |

The Help PDF is served from the bundle (`/user-guide.pdf`), not R2, so Help worked throughout.

### How the photograph import works — and how it can fail silently

On the **first page load by an authenticated administrator** whose `must_change_password` is 0,
`importRequestedProfilePhotos()` (`worker/index.js:727`) writes the seven embedded photographs into
R2 and sets `avatar_key` / `avatar_version` on the matching `user_directory` rows.

Three properties matter:

1. **It matches on email AND exact first/last name** (`index.js:733`). A directory row whose name was
   edited will silently not match, and that person gets no photo.
2. **Each photo has its own `app_meta` completion marker** (`profile_photo_import:<batch>-<key>`).
   A marker is written only on success, so a failed photo retries on the next admin visit — but a
   *successful* one never re-runs.
3. **Failures are swallowed** — the `catch` logs to `console.error` and continues (`index.js:747`).
   Nothing surfaces in the UI. Absence of an error is not evidence of success.

So verify by counting rows and objects, not by looking for errors:

```sh
# how many directory rows now carry a photo (expect 7)
npx wrangler d1 execute DB --remote --yes \
  --command "SELECT COUNT(*) AS with_photo FROM user_directory WHERE avatar_key IS NOT NULL"

# how many objects actually landed in the bucket (expect 7)
npx wrangler r2 object get dnc-tracker-assets --help >/dev/null 2>&1
npx wrangler d1 execute DB --remote --yes \
  --command "SELECT key FROM app_meta WHERE key LIKE 'profile_photo_import:%'"
```

If the counts disagree, the D1 metadata and the bucket are out of step — re-running the import will
not fix an already-marked photo. Clear that photo's `app_meta` marker to force a retry.

## ⚠ Bundle size

```
pages-dist/_worker.js   3.68 MB raw   /   2.57 MB gzip
```

That is **~85% of the 3 MB gzip script limit** on the free plan. `npm run build:pages` prints the
figure on every build and **fails** if it crosses the limit. The bundle is large because the Help PDF
and seven photographs are base64-embedded by `scripts/bundle.mjs`. If the deploy is rejected for size,
the fix is to serve those from R2 instead of embedding them — which is another reason R2 matters.

Confirm the current limit at `developers.cloudflare.com/workers/platform/limits/` before relying on
this headroom.

## ⚠ Security notes

- **`ALLOW_PLATFORM_AUTH` must stay `"false"`.** When true, `platformUserFrom()`
  (`worker/index.js:154`) trusts `oai-authenticated-user-*` request headers. On ChatGPT Sites a trusted
  proxy injected those; on a public Pages deployment nothing strips them, so **any caller could send one
  and arrive as an administrator.**
- **`business_unit_scope` is stored but never enforced.** It appears in no `WHERE` clause anywhere in
  the codebase, so a reviewer scoped to one business unit still sees and can export the entire
  portfolio. This is a known, vendor-documented gap (`IMPLEMENTATION_NOTES.md` §1). **Do not grant
  access to a business-unit-restricted reviewer until it is resolved.**
- **This deployment contains real client data** — 73 named Delaware North / Patina staff with corporate
  email addresses, 7 identifiable photographs, and 74 real capital projects with budgets. It belongs
  only in the client's own Cloudflare account. Verify `wrangler whoami` before every deploy.
- No credentials are stored in this repository. `.env` (local preview only) and all build output are
  gitignored.

## Rollback

Pages retains previous deployments; roll back from the dashboard
(**Workers & Pages → dnc-tracker-pilot → Deployments → ⋯ → Rollback**). Note that a rollback reverts
**code only** — D1 data is not versioned, so take a backup before any migration or data operation:

```sh
npx wrangler d1 export DB --remote --output backup-$(date +%Y%m%d).sql
```
